Outputs tab = what this agent produces. Editable. Summary.md is always first — your 3-second read on this agent's perspective.

Inputs tab = what drives this agent. Read-only. Shows which agent owns each input. You can see the full dependency chain: QA reads src/** (Worker's outputs) and plan/tasks.md (Planner's outputs). When those change and QA is in watch mode, it runs.

The wiring is visible. You don't need to understand glob patterns to see that QA watches the code and the task list. The UI resolves the globs into concrete files with ownership labels.

Output artifacts = what the agent owns. Input artifacts = what drives it and what it watches in watch mode. No separate watch patterns — if you want an agent to react to a file, you declare it as an input. The data flow is the trigger.

Self-subscription note — agents can add input artifacts at runtime via MCP tool. Those additions show up here and the human can see/remove them. Transparency on what the agent has wired itself into.

Chat

Freeform human-agent conversation. Agent has full tool access — it can read files, check git, commit changes, queue other agents mid-conversation. If opened from a feed item or artifact, that context is pinned.

Chat is where the human drops into the loop. The agent isn't just answering questions — it's taking actions. It committed a file change, queued another agent, and started a test run, all from the conversation. Those actions will show up in the feed and trigger downstream agents.

Context pinning — the chat was opened from the QA agent's artifacts view, so qa/bugs.md is pinned as context. The agent knows what you're looking at.

│  ⚙  Settings                                        │
│                                                      │
│ FLOW                                                 │
│                                                      │
│  Feed                                                │
